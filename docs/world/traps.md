# Traps - what looks right and is wrong

Append-only. One entry per trap, three lines at most, naming the wrong path taken
and the command that proves the trap still applies.

- 2026-11-16 — a new module under `packages/touch_grass/` reaches the CLI but not `loam`: `packages/loam/manifest.toml` resolves `touch_grass` with `source = "hex"`, so `gleam build` in loam compiled the published 0.4.4 and reported `Unknown module type` for the local file in 0.15 s wall, while `packages/gleam_cli/manifest.toml` resolves it as `{ path = "../touch_grass" }`, so the build that produces `dist/eyg` does see the local tree. Wire a new effect by changing the runtime and building the CLI; publish or restate a dependency only when a standalone `loam` build must agree. verify: `grep -q 'source = "hex"' packages/loam/manifest.toml && grep -q 'touch_grass = { path = "../touch_grass" }' packages/gleam_cli/manifest.toml`
- 2026-11-16 — `pi install npm:@woksin/pi-context-budget -l` and `"compaction": {"enabled": false}` in `.pi/settings.json` do not stop the session that is running: pi resolves packages and settings at `session_start`, so the session that started before the install committed 3 native compactions and 0 by hook on 2026-11-16, and the handoff text it wrote is unrecoverable. Prove the plane a fresh process resolves with `node /home/chexxor/Git/pi-durable-harness/scripts/diagnose-context-budget.mjs` (2 s wall, prints `context-budget extension paths=` and per-session `native compactions=`/`by hook=`); the fix applies from the next `session_start`, and `pi-eyg-codemode` installs are the same kind of artefact. verify: `test -f .pi/npm/node_modules/@woksin/pi-context-budget/src/extension.ts && grep -q '@woksin/pi-context-budget' .pi/settings.json`
- 2026-11-16 — the CLI on `PATH` is not the CLI in the tree: `~/.local/bin/eyg` is the prebuilt v0.1.0 release, whose help has no `--policy`, so `eyg run -c <code> --policy <module.eyg>` read `run` as a program path and printed `error: no such file: <cwd>/run` in 0.6 s wall while the program never ran. A tool that spawns a runner must probe `--help` for the flag (`grep -c -- '--policy' <<< '~/.local/bin/eyg --help'` prints 0), and the gated runner is `packages/gleam_cli/dist/eyg` after `./bin/compile` (0.5-0.6 s to compile, 2-3 s per gated call). verify: `! ~/.local/bin/eyg --help 2>&1 | grep -q -- '--policy'`
- 2026-11-16 — the tool result of a `run` mode call is the status line, not the value: `let r = perform ReadFile(...) r` through the gated runner printed nothing and exited 0 in 0.16 s wall, while a program ending in a bare `let` fails with `error: unexpected end of input`, so a run-mode program ends with an expression *and* with `perform StandardOut(...)` when the payload matters - a refusal left as the trailing value is invisible in `run` mode. verify: `grep -q 'In .run. mode nothing is' pi-eyg-codemode/skills/eyg-codemode/SKILL.md`

- 2026-11-15 — a refusal is a value, and discarding it looks like success: a program of `let _ = perform WriteFile(...)` then `perform StandardOut("wrote")` run under deny-all printed `wrote` with exit 0 in 0.07 s wall while the file was never written, so the answer of an effect is the evidence and the exit status is not. verify: `grep -q "let _ = perform WriteFile" pi-eyg-codemode/skills/eyg-codemode/SKILL.md`
- 2026-11-15 — a one-shot `eyg run -c` is not gated: on 2026-11-15 `eyg run -c 'perform WriteFile({path: "/tmp/eyg-proof/outside/escape.txt", ...})'` wrote the file in 0.06 s wall and an ungated `Fetch` wrote 577 bytes from `example.com` in 1.46 s wall, so anything put in front of an agent has to be started with `--policy <module.eyg>`; the gated form refuses with the policy reason and leaves nothing behind. verify: `grep -q 'args.Run(input:, policy: None) -> run.execute(input, config)' packages/gleam_cli/src/eyg_cli.gleam && grep -q 'policy_runner.run(input, policy, config)' packages/gleam_cli/src/eyg_cli.gleam`
- 2026-11-15 — `pi --mode json "prompt"` with a terminal stdin never exits: it kept the session interactive and burned 11 turns before a 300 s timeout, so a live agent session is an event, not a loop. One-shot needs `--print` with the mode, and the session then costs 44-142 s wall (`@measured 2026-11-15`). verify: `grep -q -- '--print' guides/pi_codemode_agent.md`
- 2026-11-15 — the toolchain is host-local, not repository state: `eyg`, `gleam` and `bun` resolve to `~/.local/bin/`, `erl` and `escript` are still absent, so `gleam build`/`gleam test` have no Erlang runtime and only the EYG side can run. Never quote a suite result without running `command -v` here first. verify: `command -v eyg && ! command -v erl`
